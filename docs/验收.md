# 干净机器验收

> 目的：**按一个陌生人拿到仓库之后的方式走一遍**，而不是在你已经把一切都装好的机器上点两下。
>
> 这台机器上所有测试都能过，不代表别人能装上。差别就在"没装过"这三个字。

---

## 零、发版前先冲一遍（不用另一台机器）

每次 push 完，先换个目录 clone 一份，在那里跑：

```bash
git clone https://github.com/Dsir-cmd/memory-sea <别处的目录>
cd <别处的目录>
install.cmd --dry
node scripts/check.mjs
node scripts/check-links.mjs
node scripts/verify-clean.mjs
node scripts/smoke.mjs
```

**为什么非要多这一步**：本地目录跑得通，不代表 clone 下来跑得通。
`install.cmd` 曾经是 LF 换行 + 中文，本地双击没事（我从来没双击过），
clone 到干净目录才发现 cmd.exe 报一堆 `'DE_BIN' is not recognized`——全平台装不上。

这类问题只有"换一个目录重新拿一份"才照得出来。

---

## 一、带什么

| 东西 | 为什么 |
|---|---|
| 这个仓库（U 盘 / 网盘 / git clone） | 被测对象 |
| DSH 安装包 | 干净机器没有 |
| AstrBot 安装包 + LivingMemory 插件目录 | 场景 B、C 才需要 |
| 这份清单 | 别凭记忆走 |

**不需要**：你的记忆库、你的 `data/`、你的任何配置。**故意不带**——
带了就测不出"别人装不上"。

---

## 二、关于 node

`install.cmd` / `install.sh` 自己会去找 node（先看 PATH，再看 DSH 自带的
`~/.dsh/dsh-runtimes/*/dependencies/node/bin/`），**所以装的时候不需要系统里有 node**。

只有体检脚本 `doctor.mjs` 需要，两条路：

1. 手动指：`<node.exe 的路径> scripts\doctor.mjs`
2. 跳过它——安装脚本已经做了同样的检查，把它的输出当证据

## 三、两种装法，都测一遍

### A 法：手动（验脚本本身）

```text
install.cmd --dry     # 先看会改什么
install.cmd           # 真改
```

### B 法：交给 agent（**这是真实用户路径**）

把仓库地址丢给 agent，说一句「装这个」，然后**什么都不做**，看它：

- [ ] 有没有去读 `AGENTS.md`
- [ ] 有没有先跑 `--dry`（不是必须，但说明它在谨慎）
- [ ] 退出码 2 的时候有没有停下来问，而不是硬装 AstrBot
- [ ] 最后有没有只说要「重启 DSH」，而不是写一大段
- [ ] 出问题时有没有按「卡在哪 / 试过什么 / 需要你」三段式报

**B 法测的不是脚本，是脚本够不够让一个 agent 读懂。**
如果 agent 得反复问你，说明 `AGENTS.md` 写得不够硬。

> 记录时把 agent 的**原话**粘下来。改 `AGENTS.md` 全靠这些原话。

## 四、三个场景，按顺序走，别跳

### 场景 A：只有 DSH，没有 LivingMemory

**这是最重要的一步。** 它测的是"最坏情况"：一个人听说这插件、装了 DSH、还没装 LM。

```text
1. 装 DSH，启动，确认能正常打开
2. 把仓库放上去（clone 或拷贝）
3. A 法或 B 法装一次（见上一节）
4. 重启 DSH
```

**期望**：

- [ ] 左侧导航出现「记忆海」
- [ ] 点开**不白屏**，能看到空的海或一句"还没找到记忆库"的提示
- [ ] DSH 日志里有 `[memory-sea]` 开头、没有红色堆栈
- [ ] `install` 的退出码是 `2`，且说清了"缺 LivingMemory"
- [ ] 安装没往任何地方写文件（除了 `data/config.json` 和 profile 那条 link）

**这一关过了，说明最坏的情况不会把人劝退。**

---

### 场景 B：加上 LivingMemory（不装桥）

```text
1. 装 AstrBot
2. 把 LM 放进 <AstrBot>/data/plugins/
3. 重启 AstrBot，配好 embedding provider
4. 随便聊几轮，/lmem status 确认在记
5. 重跑 install（它这次应该自动找到库）
6. 重启 DSH
```

**期望**：

- [ ] 面板里出现点（不是空的）
- [ ] 检索框里搜一个刚聊过的词，能搜到
- [ ] 点开一条记忆，右侧有详情
- [ ] `install` 退出码 `0`，`--json` 里 `dbPath` 是对的
- [ ] DSH 聊天时模型知道 LM 里的事（注入块生效）

**这一关测的是 README 第二段——"让对方能直接照做"。**
哪一步卡住，就说明那一步写得不够清楚。

---

### 场景 C：加上写入桥

```text
install.cmd --bridge
```

然后：

- [ ] `http://127.0.0.1:8792/health` 里 `engine: true`
- [ ] `data/config.json` 里 `capture.tokenFile` 指对了
- [ ] 手动把 `capture.enabled` 改成 `true`，重启 DSH
- [ ] DSH 日志出现 `DSH 记忆已写入 livingmemory：N 条`
- [ ] AstrBot 日志出现 `[lm-bridge] 收下一条记忆`
- [ ] 在 LM 面板里能搜到这条（作用域配对正确，见 `docs/scope.md`）

## 五、判定表

| 症状 | 八成是什么 | 看哪里 |
|---|---|---|
| 导航里没有「记忆海」 | bundles 没加 / 没重启 | profile 的 `package.json` |
| 点开一片空白，连提示都没有 | `client.js` 报错 | 页面 F12 → Console |
| `install` 退出码 1 | 没 profile / Node 太老 | 它的 `PROBLEM:` 行 |
| 面板有提示但没点 | 库路径不对 | `data/config.json` 的 `dbPath` |
| 有条目但搜不到 | 中文分词 / FTS 表不同 | 看 `LIKE` 兜底能不能命中 |
| 写了但 QQ 那边想不起来 | 作用域没对上 | `docs/scope.md` |
| 装完 DSH 起不来 | profile 的 JSON 写坏了 | 同目录的 `package.json.bak-*` |
| agent 反复来问 | `AGENTS.md` 不够硬 | 把它的原话记下来 |

## 七、出了事带什么回来

四样，缺一样都会多绕一圈：

1. `install` 与 `doctor` 的**完整输出**（它们已经把大部分判断做完了）
2. DSH 日志里所有 `[memory-sea]` 开头的行
3. 浏览器 F12 → Console 的红色报错（客户端问题只看得到这里）
4. 面板截图

**别带**：你的库文件、你的 config.json、你的 token。看日志就够了。
把 `dbPath` 这种路径打个码也行。
