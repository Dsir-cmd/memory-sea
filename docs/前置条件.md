# 你得先有什么

> **前提：DSH 已经装好了。** 这个仓库只讨论「窗」能不能开，不讨论「房子」怎么盖——
> 你在 DSH 里运行它，那件事就已经成立。
>
> 记忆海不是一套完整的机器人。它是一扇窗，**窗后面必须有一个已经装好的 LivingMemory**。
> 这一页只干一件事：让你知道自己站在第几步。

---

## 最省事的判断方式：先跑一次

```text
install.cmd        # Windows
./install.sh       # macOS / Linux
```

它会把你缺的那层逐个探一遍，然后直接告诉你缺什么、缺在哪个目录：

```text
STATUS: partial
ASTRBOT: <它找到的 AstrBot 目录>
PLUGINS_DIR: <LM 应该放进去的那个目录>
PROBLEM: AstrBot 在 …，但里面没有 LivingMemory
```

**先跑，再读。** 下面这些是它报错时你要用的背景。

---

## 往上要补的，只有三层

```text
第 1 层   AstrBot        ← LivingMemory 的宿主
第 2 层   LivingMemory   ← 记忆本体
第 3 层   记忆海          ← 本仓库
```

| 层 | 怎么判断有没有 | 没有的话 | 能跳过吗 |
|---|---|---|---|
| AstrBot | 磁盘上有 `AstrBot` / `AstroBot` 目录，里面有 `data` 或 `instances` | 去 [AstrBot 仓库](https://github.com/AstrBotDevs/AstrBot)，按[官方文档](https://docs.astrbot.app)装 | **不能**，LM 是它的插件 |
| LivingMemory | 有 `livingmemory.db` 这个文件 | 见下面第 2 层 | **不能**，记忆归它 |
| 记忆海 | 左侧导航有「记忆海」 | 装本仓库 | 就是你 |

### 两件常被误会的事

**① 不需要 QQ。**

很多人以为要先"把机器人挂进 QQ"。不用。LivingMemory 只需要 AstrBot；
AstrBot 自带 WebUI，你在里面打字它就记。**QQ 是"让机器人住进 QQ 里"，那是另一件事，随时可以之后再做。**

所以最短验证路径是：AstrBot 装好 → 在它的 WebUI 里聊两句 → 有记忆了 → 装记忆海看海。全程不碰 QQ。

**② 不需要先有一个人设。**

LM 记的是对话，不管你的机器人叫什么、什么脾气。这些是上层的事。

## 每一层的最短路径

### 第 1 层 · AstrBot

- **判断**：有没有 `AstrBot`（或 `AstroBot`）目录，里面有没有 `data` 或 `instances`。
  安装脚本会替你找这几个常见位置。
- **没有**：[AstrBot 仓库](https://github.com/AstrBotDevs/AstrBot) → 按[官方文档](https://docs.astrbot.app)装，
  Windows 有一键包。
- **装完先确认**：能启动、能在它的 WebUI 里说句话。**这一步不过，别往下走。**

> AstrBot 是个多平台机器人框架。这里只用到它最基础的能力：跑插件、连模型。
> 它自己的一大堆功能你都可以先不管。

### 第 2 层 · LivingMemory

- **判断**：有没有这个文件

  ```text
  <AstrBot>/data/plugin_data/astrbot_plugin_livingmemory/livingmemory.db
  ```

  多实例装法的路径是 `<AstrBot>/instances/<实例>/core/data/plugin_data/astrbot_plugin_livingmemory/livingmemory.db`。

- **没有**：三步

  1. 把 LM 放进 AstrBot 的插件目录（安装脚本会打印确切路径，一般是 `<AstrBot>/data/plugins/`）
  2. 重启 AstrBot，Python 依赖会按 `requirements.txt` 自动装
  3. 在 AstrBot 的插件配置页里找到 **LivingMemory**，填 `provider_settings.embedding_provider_id`

- **第 3 步是最容易卡的地方。** Embedding 不是聊天模型，是专门做向量化的那个；
  不填它，LM 会照常聊天、**但一条记忆都不会留下**。推荐 `BAAI/bge-m3`。
  细节看 [LM 的文档](https://lxfight-s-astrbot-plugins.github.io/astrbot_plugin_livingmemory/)。

- **验证**：在 AstrBot 里聊几轮，然后

  ```text
  /lmem status
  /lmem search 你刚说过的词
  ```

  有数字、能搜到，才算通。

### 第 3 层 · 记忆海

回到 [README 的第二节](../README.md#二再装记忆海)，或者直接跑一次安装。

## 这里为什么不教你怎么搭 QQ 机器人

刻意的，三个原因：

1. **那是 AstrBot 和 NapCat 的领域。** 它们的部署方式变化比这个插件快得多，
   在这里抄一份教程等于发一份会过期的二手资料。
2. **不必要。** 没有 QQ 一样能验证整套记忆链路——AstrBot 的 WebUI 就够了。
3. **责任边界。** QQ 登录、风控、掉线这些问题，答案在上游，不在这里。

所以本仓库只讲到这里：**你需要 AstrBot，它需要 LM，LM 需要一个 embedding provider。**
再往下的 QQ 那一段，去 AstrBot 的文档。

## 还是不行？

跑一次体检，把所有输出贴出来：

```text
<node 的路径> scripts/doctor.mjs
```

四样东西就够定位问题：安装脚本输出、`doctor` 输出、DSH 日志里 `[memory-sea]` 的行、
浏览器 Console 的报错。见 [验收.md](验收.md)。
